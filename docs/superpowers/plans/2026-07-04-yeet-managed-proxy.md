# yeet M4 — managed proxy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (inline TDD per user prefs).

**Goal:** `proxy.managed: true` — yeet owns a host-scoped Traefik (container + shared ingress
network + ACME store) shared by every yeet app on the host. `yeet bootstrap` creates it, `yeet
proxy apply` converges it, `yeet destroy` refcounts it. Design §"The proxy is owned" (rev 5).

**Architecture:** New host scope at `/var/lib/yeet/_host/` beside the per-app dirs — its own
noclobber lock (TTL, no epoch/fence: proxy converge is one short idempotent critical section,
not a resumable multi-phase deploy) and its own journal. The proxy runs as its own compose
project `yeet-proxy` rendered by yeet; the app supplies Traefik config via `proxy.config:
<dir>` (contract: `traefik.yml` required; `dynamic.yml`, `.env` optional; ACME storage must be
`/letsencrypt/acme.json`; `ping: {}` enabled — the healthcheck gates on it). Apps register in
`_host/proxy/apps/<app>` with their config hash; divergent hashes across registered apps is a
named conflict, not last-writer-wins. Role services get the shared external network injected at
render time so the host-scoped Traefik can reach them.

**Tech stack:** existing — Go, compose-go v2, Fake transport tests, CUE schema.

## Global constraints

- All existing invariants hold: injection rule (everything host-bound through `q()` or
  validated), secrets never logged, lock-order host→app (bootstrap takes host lock only for the
  proxy step, releases before app work), ACME state never churned (unchanged config = no
  container touch), data loss opt-in (`--proxy` on destroy).
- `_host` can never collide with an app: app names match `^[a-z][a-z0-9-]*$`.
- Single-host unchanged. External/none proxy paths unchanged.

## Host layout

```
/var/lib/yeet/_host/
  lock                  # noclobber, TTL by mtime, --force prints holder
  journal/<id>.jsonl    # proxy-apply / proxy-destroy events
  proxy/
    compose.yaml        # rendered by yeet (project: yeet-proxy, container: yeet-proxy)
    config.hash         # hash of the deployed config payload
    config/             # app-provided: traefik.yml [dynamic.yml] [.env]
    acme/acme.json      # mode 600, created once, never overwritten
    apps/<app>          # registration record: config hash
```

## Rendered proxy compose (kind: traefik-docker)

```yaml
# generated by yeet — do not edit
services:
  proxy:
    container_name: yeet-proxy
    image: <proxy.image | traefik:v3.7>
    restart: unless-stopped
    ports: ["80:80", "443:443"]
    env_file: [config/.env]            # only when .env present in config dir
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock:ro
      - ./config:/etc/traefik:ro
      - ./acme:/letsencrypt
    healthcheck:
      test: ["CMD", "traefik", "healthcheck"]
      interval: 30s
      timeout: 5s
      retries: 3
      start_period: 15s
    networks: [ingress]
networks:
  ingress:
    name: <proxy.network | yeet-ingress>
```

The proxy project OWNS the network (creates it); app composes reference it as `external:
true` — hence preflight asserts the proxy is up before any deploy.

## Converge semantics (the ACME-safety rule)

- unchanged (remote `config.hash` == local && compose identical && container running) → no-op.
- compose changed → upload + `up -d` (recreate; acme/ survives as a bind).
- config-only changed → upload + `docker restart yeet-proxy` (static config needs restart;
  uniform and honest — shown in the diff first).
- container absent → `up -d` regardless.

  `kind` empty defaults to `traefik-docker` when managed; managed with `kind: none` is an error.
- CUE: `proxy?: { kind?: "traefik-docker" | "none", managed?: bool, image?: string, config?:
  string, network?: string }`.
- Tests: managed+config valid; managed w/o config error; managed+kind none error; defaults.

### Task 2: internal/proxy package (pure)
**Files:** `internal/proxy/proxy.go`, `internal/proxy/proxy_test.go`
- `HostBase()` → `<YEET_BASE_DIR|/var/lib/yeet>/_host` (mirrors release.PathsFor test hook).
- `Paths` struct (Base, Lock, Journal, Dir, Compose, ConfigDir, Acme, Apps, Hash).
- `RenderCompose(image, network string, hasEnv bool) []byte` — exact shape above.
- `HashDir(dir string) (string, error)` — sha256 over sorted (relpath, content) pairs.
- `Stage(localCfgDir, stagingDir, image, network string) (hash string, err error)` — copies
  config/, writes compose.yaml, validates `traefik.yml` present, returns hash of the whole
  staged payload.
- Tests: render golden (env/no-env), hash stability/ordering, stage validates traefik.yml.

### Task 3: ingress network injection at render
**Files:** `internal/compose/render.go`, `internal/compose/render_test.go`
- `InjectProxyNetwork(p *types.Project, network string)` — every ROLE service (not jobs, not
  accessories… roles only: they serve traffic) gets `networks: {default: {}, <network>: {}}`
  preserving default connectivity; project gains `networks: <network>: {name: <network>,
  external: true}`.
- Wire in `stageRelease`/`render` when `cfg.Proxy.Managed`.
- Tests: role service has both networks; accessory untouched; network marked external.

### Task 4: host lock
**Files:** `internal/engine/proxylock.go`, `internal/engine/proxylock_test.go`
- `acquireHostLock(ctx, force) error` / `releaseHostLock(ctx)` — same noclobber + TTL-by-mtime
  + holder-JSON protocol as the app lock, at `_host/lock`; no epoch, no fence.
- Tests (Fake): acquires when free; refuses fresh holder; takes over expired; force breaks.

### Task 5: EnsureProxy + ProxyApply
**Files:** `internal/engine/proxy.go`, `internal/engine/proxy_test.go`
- `EnsureProxy(ctx, force bool) error`:
  1. local stage (proxy.Stage) → hash
  2. host lock
  3. mkdir tree; `touch acme/acme.json && chmod 600` only-if-absent
  4. conflict check: read `apps/*`; another app with different hash → error naming both
     (unless force)
  5. read remote `config.hash` + remote compose; decide no-op / up / restart per rules above;
     show unified diff of compose when changed (reuse difflib pattern)
  6. upload staging → `_host/proxy/`, write `config.hash`
  7. converge; wait healthy on the `yeet-proxy` container
     (`docker ps -q --filter label=com.docker.compose.project=yeet-proxy`)
  8. write `apps/<app>` = hash; journal (App: `_host`) start/finish
  9. release host lock (deferred)
- `ProxyApply(ctx, force)` = EnsureProxy for the CLI verb.
- Tests (Fake): fresh host creates+ups+registers; unchanged is no-op (no up, no restart);
  config-only change restarts; conflict with second app errors + force proceeds; acme.json
  never touched when present.

### Task 6: bootstrap + preflight integration
**Files:** `internal/engine/bootstrap.go`, `internal/engine/preflight.go` + tests
- Bootstrap: after registry login, before accessories: `if cfg.Proxy.Managed → EnsureProxy`.
  (Host lock acquired inside EnsureProxy and released before the app work continues — the
  fixed order.)
- Preflight (deploy path): managed → `yeet-proxy` container running + healthy, else error
  "run `yeet bootstrap` or `yeet proxy apply`".
- Tests: bootstrap with managed proxies ensures before accessories-up; preflight fails when
  proxy absent.

### Task 7: destroy refcount
**Files:** `internal/engine/ops.go`, `cmd/yeet/ops.go` + tests
- Destroy: after app teardown, `rm -f _host/proxy/apps/<app>`. Then: `--proxy` flag → if
  registry now empty: `docker compose -p yeet-proxy -f _host/proxy/compose.yaml down` +
  `rm -rf _host/proxy`; if registry non-empty: refuse, name remaining apps. No `--proxy` →
  log hint if registry empty.
- Tests: destroy deregisters; --proxy with empty registry tears down; --proxy with other app
  registered refuses.

### Task 8: CLI + docs
**Files:** `cmd/yeet/ops.go` (proxy cmd), `README.md`
- `yeet proxy apply [--force]` — loadAll, connect, `e.ProxyApply`.
- README: managed proxy section — contract (traefik.yml, ping, /letsencrypt/acme.json),
